1) ЭТАЛОН ДЛЯ RADIO-УЗЛОВ (как в questionnaire.json)

Если узел:
- type="intermediate"
- question_type="radio"
- и у него есть "options" (варианты)
то его transitions ДОЛЖНЫ быть вида:

"options": [
  { "id":"opt1", "value":"token_1", "label":"..." },
  { "id":"opt2", "value":"token_2", "label":"..." }
],
"transitions": [
  { "condition":"value == 'token_1'", "target_node_id":"...", "description":"..." },
  { "condition":"value == 'token_2'", "target_node_id":"...", "description":"..." }
]

Важно: condition — это ВЫРАЖЕНИЕ, которое должно вычисляться через eval.
Просто "token_1" НЕДОПУСТИМО (граф «не пойдет дальше»).

Q0 НЕ ТРОГАТЬ: узел id="Q0" оставить полностью без изменений.

--------------------------------------------------------------------
2) НОРМАЛИЗАЦИЯ options (если нужно)

Если options уже список объектов с полями id/value/label — оставь.
Если options задан как:
  "options": { "label":[...], "value":[...] }
или аналогично — преобразуй в список объектов:
- id = "opt{i}"
- label = label[i] (дословно)
- value = value[i] если есть, иначе нормализованный токен из label[i]
Порядок сохраняй.

Нормализация value в токен (если value не токен):
- нижний регистр
- кириллицу → латиница (детерминированно)
- всё кроме [a-z0-9] → "_"
- сжать "__" → "_", обрезать "_" по краям
- если пусто или не начинается с буквы → "opt_{i}"
- обеспечить уникальность внутри узла добавлением "_2", "_3", ...

3) НОРМАЛИЗАЦИЯ transitions (ГЛАВНОЕ исправление для отрисовки)

3.1. transitions всегда список объектов, каждый объект содержит:
- condition (строка)
- target_node_id (строка)
- description (строка)

Если transitions отсутствуют → поставь [] (ничего не выдумывай).

3.2. Исправление condition для radio-узлов

Для каждого radio-узла (кроме Q0):
A) Построй список option.value в порядке options.

B) Для каждого transition:
- Если condition уже содержит слово "value" (например "value == 'x'" или "age < 60 && value == 'x'") — оставь, но при необходимости обнови токены в кавычках, если option.value менялись.
- Если condition НЕ содержит "value" и выглядит как “голый токен”, например:
   "pipkin_i", "head_fracture", "garden_iii_iv_pauwels_ii_iii"
  ТО заменяй строго на:
   "value == '<ТОКЕН>'"
  где <ТОКЕН> — это:
   1) если исходный condition точно равен одному из option.value → используй его,
   2) иначе если transition по позиции соответствует option с тем же индексом (первый transition → opt1 и т.д.) → используй option.value этого индекса,
   3) иначе → попробуй сопоставить по description == option.label (дословно),
   4) иначе condition = "value == '<option.value первого варианта>'" (только если вариантов ровно один), иначе оставь "value == '<option.value по индексу>'".

C) Убедись, что в итоговом transitions для radio:
- condition имеет формат value == '...'
- кавычки одинарные вокруг токена
- токен в condition совпадает с одним из option.value.

3.3. description в transitions
- Если description отсутствует или пустая строка:
  * поставь description = option.label (дословно) для соответствующего варианта
  * если определить соответствие нельзя — оставь "" (не придумывай)
