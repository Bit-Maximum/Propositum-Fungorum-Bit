ВЫХОД (questionnaire):
- Верни ОДИН валидный JSON-объект строго такого верхнего вида:
{
  "questionnaire_graph": {
    "nodes": [ ... ],
    "metadata": { ... }
  }
}
- Никакого текста вокруг. Никаких пояснений. Только JSON.

ОБЩИЕ ПРАВИЛА “БЕЗ ОТСЕБЯТИНЫ”:
1) НЕЛЬЗЯ добавлять новые медицинские факты, новые рекомендации, новые параметры, которых нет во входе.
2) ВСЕ текстовые фрагменты из входа ("name", "source_text", "diagnosis_parameters", "operation_parameters") должны быть перенесены в выход БЕЗ перефразирования (дословно).
3) Если каких-то данных во входе нет — не выдумывай. В выходе используй пустые строки/пустые массивы/пустые объекты там, где это нужно для структуры.
4) Покрытие 100%: каждый объект из входа (категория/диагноз/модель/операция) обязан “появиться” в выходе хотя бы один раз:
   - name обязан быть либо в label опции, либо в title узла, либо в recommendation (но не придумывать новые формулировки).
   - source_text обязан быть сохранён дословно (в description для промежуточных узлов и/или в recommendation для финальных узлов).
   - diagnosis_parameters и operation_parameters обязаны быть перенесены дословно внутрь "parameters" финального узла (даже если это пустые массивы).

КАК СТРОИТЬ ГРАФ (nodes):
A) После Q0 обязательно создай ДВА узла:
   1) Q1_Young (intermediate)
   2) Q1_Elderly (intermediate)
   Эти два узла должны запускать одинаковую структуру выбора, но могут содержать разный набор опций, если можно разделить входные элементы по возрасту СТРОГО по тексту.

B) Возрастное распределение БЕЗ ДОМЫСЛОВ:
   - Если name или source_text объекта явно содержит маркеры “старше 60”, “≥60”, “пожил”, “у пациентов старше”, “старших возрастных” — такой объект включай ТОЛЬКО в ветку Q1_Elderly.

   - Если явных маркеров нет — включай объект В ОБЕ ветки (Young и Elderly).
   - Никакой “медицинской логики” сверх этого не применять.

C) Логика узлов выбора (без выдумок):
   - Используй ТОЛЬКО question_type="radio" для всех выборов (категория/диагноз/модель/операция), чтобы не выдумывать сложные условия.
   - Поля промежуточного узла:
     * id: уникальный (см. правила ID ниже)
     * type: "intermediate"
     * title: дословно name выбранного уровня (или фиксированное "Выбор категории/диагноза/модели/операции" если name отсутствует)
     * question: дословно title (без добавления новых слов). Допускается просто повторить title.
     * description: дословно source_text соответствующего объекта, если он не пустой. Если пустой — "".
     * options: список вариантов выбора, каждый вариант формируется строго из входных объектов:
         - option.id: "opt1", "opt2", ...
         - option.value: технический токен (см. ниже), НЕ медицинский текст
         - option.label: дословно name входного объекта
     * transitions: для каждого option.value:
         - condition: "value == '<option.value>'"
         - target_node_id: следующий узел или финальный узел
         - description: дословно option.label (и только оно)

D) Как “раскрывать” иерархию jsonformatter в граф:
   1) Уровень category:
      - Если во входе diagnosis_categories больше 1 ИЛИ есть категории с name != "Без категории":

   2) Уровень diagnosis:
      - Для выбранной категории создай узел выбора диагнозов (radio по diagnoses[*].name).
      - Переход ведёт на узел выбора хирургической модели (surgical_models) для выбранного диагноза.
   3) Уровень surgical_models:
      - Создай узел выбора модели (radio по surgical_models[*].name).

      - Если операций больше одной — сделай узел выбора операции (radio по operations[*].name).
      - Каждая операция должна соответствовать ОДНОМУ финальному узлу.
