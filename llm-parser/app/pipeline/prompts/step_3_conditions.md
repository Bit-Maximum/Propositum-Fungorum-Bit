Ты — разработчик клинических decision-support систем для ХИРУРГИЧЕСКОГО лечения.
Твоя задача: создать JSON файл questionnaire_graph на основе предоставленной клинической рекомендации.

### ОБЯЗАТЕЛЬНЫЕ ТРЕБОВАНИЯ:

1. **Структура файла:**
   - Копируй стандартную структуру из эталонного файла (RADIUSBONE.json v2.2)
   - Все ID остаются на английском (Q0, Q1_Young, R_Final_Name и т.п.)
   - Весь текст, вопросы, ответы, рекомендации ТОЛЬКО НА РУССКОМ
   - Исключение: унифицированная медицинская терминология (AO/OTA, ORIF, IMN, LCP, ACDF и т.п.)

2. **Единство языка и грамматики:**
   - Анализируй падеж, число и род в предоставленном файле клинической рекомендации
   - Все question, label, recommendation — в ОДНОМ падеже/числе на протяжении всего файла
   - Если рекомендация говорит: "Пациент с переломом требует...", то везде "пациент", "требует" (не смешивай с "пациентам требуются")
   - Согласованность: "молодые" или "молодые пациенты" (выбери один вариант и придерживайся везде)

3. **АВТОМАТИЧЕСКОЕ ОПРЕДЕЛЕНИЕ КЛЮЧЕВЫХ РЕШАЮЩИХ ФАКТОРОВ из клинической рекомендации:**
   
   **Алгоритм анализа:**
   - Прочитай весь документ и выяви ОСНОВНЫЕ критерии разделения на группы лечения
   - Для ПЕРЕЛОМОВ ищи: возраст, локализация, тип (AO/OTA), смещение, состояние мягких тканей, открытость, остеопороз
   - Для ГРЫЖ ищи: возраст, неврологический статус (миелопатия/радикулопатия), длительность симптомов, прогрессирование, синдром конского хвоста
   - Для ТРАВМ ищи: механизм, острые осложнения, кровотечение, инфекция, функциональный статус
   - Для ДЕГЕНЕРАТИВНЫХ ЗАБОЛЕВАНИЙ ищи: возраст, функциональность, сопутствующая патология, консервативное лечение (сроки и эффект)
   
   **Результат анализа:**
   - Составь СПИСОК из 3–5 основных факторов
   - Каждый фактор → отдельный узел Q или группа узлов
   - Факторы располагай в логическом порядке: возраст → диагноз/локализация → характеристики/тяжесть → осложнения/показания
   
   **Пример для переломов:**
   ✓ Возраст (Q0: <60 vs ≥60) — всегда первый фактор
   ✓ Локализация/тип перелома (Q1: где и какой тип?)
   ✓ Состояние мягких тканей (Q2: закрытый/открытый/повреждение?)
   ✓ Степень смещения/фрагментации (Q3: простой/сложный/оскольчатый?)
   ✓ Качество кости (Q4: остеопороз у пожилых?)
   
   **Пример для грыж:**
   ✓ Возраст (Q0: <60 vs ≥60)
   ✓ Локализация (Q1: шейный/поясничный отделы?)
   ✓ Неврологический статус (Q2: радикулопатия/миелопатия/боль?)
   ✓ Выраженность симптомов (Q3: легкая/выраженная/прогрессирующая?)
   ✓ Длительность консервативного лечения (Q4: < 6 недель / ≥ 6–8 недель?)

4. **Логика граф-структуры:**
   - Q0 → age validation → Q1_Young / Q1_Elderly (ОБЯЗАТЕЛЕН для ≥60 / <60)
   - Q1 → первичный диагностический вопрос (локализация, тип, основной синдром)
   - Q2+ → уточняющие вопросы (характеристики, тяжесть, осложнения, мягкие ткани)
   - Каждый вопрос → 2–5 вариантов ответа (медицински значимые)
   - R_* → final nodes (ВСЕГДА type: "final", содержат хирургическую рекомендацию)
   - КАЖДЫЙ transition → ДОЛЖЕН иметь соответствующий target node (NO missing links!)

5. **Формат вопросов (intermediate nodes):**
   - id: Q[Number]_[Category] или Q[Number]_[Young/Elderly]_[Category]
   - type: "intermediate" (ВСЕГДА)
   - title: "НАЗВАНИЕ ВОПРОСА (молодые)" или "(пожилые)" — обязательно указывай возрастную группу если есть разделение
   - question: Начинай с глагола или существительного, ясный и медицински корректный вопрос
   - question_type: "radio" (один выбор) или "checkbox" (множественные признаки)
   - options: массив с id, value, label (минимум 2–3 медицински значимых варианта)
   - transitions: условие → target_node_id (проверь что узел СУЩЕСТВУЕТ!)
   - description: краткое описание перехода
   
   **ВАЖНО: Не допускай одиночные варианты ("Да, подтверждено") — это должна быть РАЗВИЛКА!**

6. **Формат рекомендаций (final nodes):**
   - id: R_[Young/Elderly]_[MethodName] (например: R_Young_ORIF_Volar, R_Elderly_Conservative)
   - type: "final" (ВСЕГДА)
   - title: "РЕКОМЕНДАЦИЯ: [краткое название метода] ([возрастная группа])"
   - recommendation: 1–3 предложения, практическое ХИРУРГИЧЕСКОЕ действие, медицинская логика
   - Используй повелительное наклонение: "показана", "требуют", "рекомендуется", "лечат"
   - Если есть дополнительные параметры (техника, показания, сроки) → добавь в parameters (опционально)
   
   **Примеры хирургических рекомендаций:**
   ```json
   {
     "id": "R_Young_ORIF_Plate",
     "type": "final",
     "title": "РЕКОМЕНДАЦИЯ: Остеосинтез пластиной (молодые)",
     "recommendation": "Показана открытая репозиция и остеосинтез волярной блокируемой пластиной с восстановлением анатомических параметров и ранней мобилизацией."
   }
7. Специфика ХИРУРГИЧЕСКИХ рекомендаций:

Фокус ТОЛЬКО на хирургическое лечение (не консервативное, если не указано как альтернатива)

Если консервативное лечение — оно может быть в graph как опция (например, при простых переломах)

Указывай методы: ORIF, IMN, EX FIX, артродез, пластика, эндоскопическое вмешательство и т.п.

Включай сроки: "экстренная" (<24ч), "срочная" (дни), "плановая" (недели)

Указывай доступы: волярный, дорсальный, передний, задний, интерламинарный и т.п.

8. Validation (критические проверки):

Все target_node_id ДОЛЖНЫ существовать в nodes массиве

Нет дублей ID

Нет пропущенных узлов (особенно final nodes с ошибками вроде "127.0.0.1")

Каждый intermediate node имеет ≥2 вариантов ответа

Каждый вариант ответа имеет transition → существующий узел

Весь русский текст в едином падеже/числе

Все final nodes имеют type: "final" и содержат хирургическую рекомендацию

metadata заполнена корректно

JSON валидный (синтаксис проверен)
