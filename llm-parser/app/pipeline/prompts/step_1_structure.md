   - переименовывать
   - сокращать
   - обобщать
   - классифицировать

4. Если ты сомневаешься, к какому уровню отнести фрагмент —
   помещай его на САМЫЙ НИЖНИЙ возможный уровень.
5. НЕ создавай сущности, которых нет в тексте.

Извлеки ТОЛЬКО структуру хирургического лечения.
ИСКЛЮЧИ: условия, причины, показания, возраст, противопоказания, цели, прогнозы, сравнения.


ПРАВИЛА ДЛЯ operation_parameters:
1. operation_parameters — это любые дословные технические, инструментальные или конструктивные характеристики операции, указанные в том же абзаце.
в том числе:
- количественные значения
(например: "25 мм", "8–10 недель", "240 мм", "15±10°")
- требования к положению, ориентации, доступу, фиксации
(например: "антеверсия 10–15°", "Tip-Apex Distance менее 25 мм")
- характеристики импланта или конструкции
(например: "бесцементная фиксация", "длина не менее 240 мм")
- варианты выполнения операции
(например: "в динамическом варианте", "в статическом варианте")
и т.д.
2. К ним ОБЯЗАТЕЛЬНО относятся фразы, начинающиеся с:
- "при помощи"
- "с помощью"
- "с использованием"
- "с применением"
- "с возможностью"
3. Каждый параметр заносится отдельной строкой массива.
4. Если параметр содержит перечисление вариантов через союзы ("или", "и", "," и т.д.), каждый вариант извлекается как отдельный элемент массива.
* Пример: Текст «с использованием бесцементной или гибридной фиксации» → ["бесцементной фиксации", "гибридной фиксации"].
* Пример: Текст «с применением пластин, винтов и спиц» → ["пластин", "винтов", "спиц"].
4. Формулировки параметров НЕ ИЗМЕНЯТЬ, брать дословно из текста.
5. Если параметры указаны списком — разбивать на отдельные элементы массива.
6. Если параметров нет — возвращать пустой массив [].

ПРАВИЛА ДЛЯ diagnosis_parameters:
1. Заполняйте ТОЛЬКО если в source_text диагноза есть:
   - классификационные коды (AO/OTA, Garden, Pipkin и т.д.)
   - типы, подтипы, номера классификаций
   - стадии, степени, индексы
2. НЕ включайте общие названия диагнозов.
3. Формулировки — строго дословно из source_text.
4. Если параметры перечислены через запятые или другие разделители — разделяйте на отдельные элементы.ф
   Пример: "31А1.3, 31A2 по классификации АО/ОТА" → ["31А1.3", "31A2"]
5. Если отсутствуют — [].

ПРАВИЛА ДЛЯ ОБРАБОТКИ ПЕРЕЧИСЛЕНИЙ:
1. Если в одном абзаце перечислены несколько диагнозов или операций — создавай отдельные элементы.
2. Если перечислены параметры — разделяй их на отдельные элементы массива.
3. Избегай дублирования: один элемент — одна сущность.

Важные ограничения
1. Уровни не могут дублироваться.
2. source_text должен быть ПОЛНЫМ текстом абзаца-источника.
3. При извлечении параметров проверяй ПОЛНЫЙ source_text, а не только name.
